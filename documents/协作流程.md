# 四人Git与文档协作流程

日期：2026-11-12。本文件规定版本分支、任务协作、文档同步、冲突处理和阶段验收方式。

## 1 分支与阶段

`main`保存稳定基线，`v1`、`v2`和`v3`分别用于三个阶段集成。成员任务分支从对应阶段分支创建，通过PR合入阶段分支。

```text
main
├─ v1
│  ├─ feat/a-v1-frontend
│  ├─ feat/b-v1-trade
│  ├─ feat/c-v1-identity
│  └─ test/d-v1-verification
├─ v2
│  ├─ feat/a-v2-frontend
│  ├─ feat/b-v2-services
│  ├─ feat/c-v2-governance
│  └─ test/d-v2-verification
└─ v3
   └─ 系统测试、质量完善与交付整理
```

阶段分支完成集成、回归和验收后合入`main`，并通过版本标签保存稳定快照。

## 2 任务流程

1. 从阶段计划和任务索引选择任务；
2. 核对需求、ADR、接口、数据及测试依据；
3. 在短任务分支完成实现和自测；
4. 同步修改相关设计、接口和运行文档；
5. 提交PR并由受影响成员审查；
6. 合入阶段分支进行联调；
7. D执行独立验证并整理证据；
8. 完成阶段验收后进入下一版本。

## 3 接口协商

接口提供方负责说明路径、身份、请求字段、响应字段、错误状态和数据变化；调用方负责核对页面与业务使用方式。无法确定的内容由相关成员协商，先输出明确问句，再共同更新OpenAPI和接口说明。

数据库升级由B统一排序；C提出身份和治理数据需要；A核对前端字段；D核对升级、权限和状态验证方法。

## 4 冲突处理

文本冲突由原作者和受影响成员共同核对业务含义。没有文本冲突时仍检查以下内容：

- 接口字段和状态码；
- 数据库升级顺序；
- 订单与物品状态联动；
- 权限及公开字段；
- 依赖和锁文件；
- 测试与文档引用。

共享文件由主维护成员整合，相关成员复核。提交历史采用正常合并方式保留任务轨迹。

## 5 文档与证据

代码与文档同步变更。设计决定记录在ADR，接口变化更新OpenAPI，阶段范围更新任务索引，测试结果进入测试报告，原始日志、JSON和截图进入证据目录。

GitHub的读取、创建分支、提交、推送、PR、Issue和仓库设置操作，均按照项目约定说明目标、动作及影响范围后逐批确认。
