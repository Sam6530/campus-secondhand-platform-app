# 运行与配置说明

版本1.0，2026-11-12。本文件规定系统的运行环境、局域网拓扑、配置项、启动顺序和数据升级责任。具体操作命令见`implementation/README.md`。

## 1 技术环境

| 项目 | 统一环境 |
|---|---|
| 前端 | Node.js、Vue 3.5、Vite 6 |
| 后端 | Java 17、Spring Boot 3.5.7、MyBatis 3 |
| 数据库 | MySQL 8，使用UTF-8字符集和UTC时间 |
| 构建工具 | npm、Maven 3.9 |
| 默认前端端口 | 5173 |
| 默认后端端口 | 18080 |
| 默认数据库端口 | 3306 |

依赖版本由`package-lock.json`和`pom.xml`锁定。开发、联调和测试环境使用相同的主版本及数据库升级序列。

## 2 本机与局域网拓扑

各成员可以在本机运行前端、后端和独立合成数据库。统一联调环境运行一套后端、MySQL和图片存储，组员通过局域网浏览器访问。

浏览器统一请求相对路径`/api`，由Vite开发代理或交付入口转发到后端。前端不直接连接MySQL。局域网访问使用联调主机的LAN地址，前后端优先采用同源入口。

系统同时支持本机进程和Docker Compose两种运行方式。两种方式共享数据库升级、配置名称和持久化规则；数据库数据及图片目录使用独立持久化存储。

## 3 配置项

仓库根目录的`.env.local`用于本机启动，`implementation/.env`用于容器编排。样例文件只保存配置名称和示例值，实际口令不进入版本控制。

| 配置 | 用途及约束 |
|---|---|
| SERVER_PORT / SERVER_ADDRESS | 后端监听端口和地址 |
| DB_URL / DB_USERNAME / DB_PASSWORD | 数据库连接、应用账号和口令 |
| API_PROXY_TARGET | 前端同源代理的后端目标 |
| FRONTEND_PORT / FRONTEND_HOST | 前端静态服务端口和监听地址 |
| UPLOAD_DIR / UPLOAD_MAX_BYTES | 图片持久化目录和单文件容量限制 |
| SESSION_TIMEOUT / COOKIE_SECURE | 会话有效期和Cookie传输属性 |
| NOTIFICATION_BATCH_SIZE / RETRY_INTERVAL | Outbox投递批次、间隔和补投策略 |
| BOOTSTRAP_ADMIN_USERNAME / BOOTSTRAP_ADMIN_PASSWORD | 首次启动时创建管理员账号 |
| DEMO_SEED | 合成演示环境的数据初始化开关 |

日志不输出数据库口令、Session、CSRF令牌和认证材料。上传类型、输入长度和容量限制在前端与后端采用相同规则。

## 4 构建与启动

标准启动顺序如下：

1. 准备MySQL数据库及应用账号；
2. 根据样例填写本机或容器配置；
3. 在`implementation/frontend`执行`npm ci`和`npm run build`；
4. 执行`implementation/build.ps1`构建后端；
5. 运行`implementation/start.cmd`启动前后端；
6. 访问`http://127.0.0.1:5173`并通过`/api/health`检查服务；
7. 使用`implementation/stop.cmd`停止本机服务。

`run-local.ps1`读取仓库根目录`.env.local`，启动后端JAR和前端`serve.mjs`。前端静态文件来自`frontend/dist`，`/api`请求代理到后端。

## 5 数据库升级与持久化

后端启动时按版本顺序执行数据库升级，并在`schema_migrations`中记录版本、说明、SHA-256校验值和应用时间。已执行的结构通过新增升级脚本升级，常规启动保留账号、业务数据和图片。

B维护升级序列、数据库健康检查和初始化流程；C核对身份、治理和聊天相关结构；A核对前端所需字段；D分别使用新建数据库和升级数据库验证升级结果。

数据库备份与图片目录共同保存。恢复时核对数据库升级版本、业务记录数量和图片资源引用，保证结构、数据与文件一致。

## 6 运行验证

运行检查按以下顺序完成：

1. 依赖及配置加载；
2. MySQL连接及结构升级；
3. 后端健康检查；
4. 前端构建与静态入口；
5. 新会话、登录和CSRF；
6. 注册认证、物品发布和订单交易；
7. 局域网另一台设备访问；
8. 服务重启后数据和图片读取；
9. 通知补投及管理操作；
10. 停止脚本清理本次启动的进程。

性能验证同时登记硬件、数据量、并发模型、持续时间和观察指标。运行结果与阶段测试用例、证据索引和验收记录相互引用。
