# 数据与状态设计

版本0.2，2026-11-24。供全组设计评审，原需求第3—5章为业务权威；物理表和约束为实现建议，不把旧数据库当新轮已建库。

## 1 数据结构和维护边界

| 对象/表建议 | 关键业务项 | 约束与读写责任 |
|---|---|---|
| accounts、identities | 内部ID、公开引用、昵称、密码哈希、角色、资格及限制 | 账户名唯一、通过校园标识唯一绑定；C负责，公开投影不含原身份 |
| verifications、verification_versions | 申请人、材料版本、原因、审核人/时间 | 当前版本条件审核，旧材料及结果保留；C |
| assets | 上传人、用途、存储引用、类型和大小 | 访问按关联对象而非猜URL；物品B使用、认证C使用，统一入口授权 |
| items、item_versions | 卖方、标题分类描述价格图片、版本、状态和隐藏 | 单件正价；版本唯一，不覆盖历史；B写内容、C审核/治理 |
| orders、reservations | 双方、标的版本及约定快照、阶段、争议标记、完成时点 | item_id至多一有效占用；订单/快照/占用/回执原子；B |
| deliveries | 订单、卖方、时间、说明、版本 | 登记不等于完成；更正追加记录，不覆盖依据；B |
| operation_receipts | 操作者、键、对象/动作、请求摘要、结果引用 | 操作者/意图键唯一，冲突不覆盖，回执不因限制变化失效；B共享机制 |
| favorites、reviews | 本人关系；订单作者、评分/内容、公开标记 | 收藏唯一，完成双方各一次；隐藏评价保留；B |
| conversations、messages | ITEM/ORDER、对象、相关双方、发送人、内容、时间 | 参与人服务端确定，终态订单只读，治理访问有依据；C |
| reports、disputes、dispute_evidence | 对象、理由、证据、当事人、状态、结论/关联事件 | 每举报独立回执；补证追加；同订单处理中争议按规则唯一；C |
| audit_facts、notification_outbox | 操作者/对象/前后值/版本；收件方/事件/状态/尝试 | 必要审计同事务；事件键去重，投递可恢复，不存密钥；C/B共同使用 |

B维护一条迁移序列，C提出身份/治理/聊天变更，全组看影响，D检查约束与可验证性。已执行迁移不就地改文件，新增升级脚本；记录执行校验和，不默认迁移工具品牌。索引围绕所有者、状态、会话参与方、订单时间和待投递查询建立，再用实际计划验证。

## 2 订单和物品的状态联动

订单：待卖方确认→待交付→待买方确认→已完成。卖方拒绝形成已拒绝；合法普通取消形成已取消；经核查争议出口可已异常终止。待买方确认沉默不自动完成或终止，管理员不能代确认。

| 事件 | 合法前态和角色 | 同一事务的结果 | 拒绝/回滚要求 |
|---|---|---|---|
| 新下单 | 双方资格、当前版本审核、未隐藏受限、无占用且非自买 | 订单/快照/占用/回执/审计及通知待发送记录 | 失败无孤单、无额外占用，不报成功 |
| 接受或拒绝 | 该卖方，待卖方确认，无禁止推进争议 | 接受转待交付；拒绝终止、释放占用、重判可售 | 其他人/阶段不写状态或处理记录 |
| 交付登记 | 该卖方，待交付，声明实际交付，无禁止登记争议 | 登记事实、阶段待买方确认、审计 | 与取消竞争时锁后重读，后到不覆盖 |
| 买方确认 | 该买方，待买方确认且已登记 | 订单完成/物品成交/占用释放、完成时间与回执 | 重试不二次统计；管理员/卖方拒绝 |
| 普通取消 | 当事人、允许阶段、声明未交付、无登记或处理中争议 | 终止、释放占用、按所有条件判断物品后态 | 已交付未登记也不能绕过事实，矛盾走争议 |
| 争议受理/补证 | 未结束订单当事人；未结案可补证 | 保持原阶段和占用，争议记录/追加证据/审计 | 补证与结案在保护后读最新状态 |
| 争议异常终止 | 管理员核查依据；原需求允许阶段 | 订单终止、不计成交、占用释放、物品异常终止不可售 | 不能自动上架/退款或伪造收货 |
| 解封/取消隐藏/恢复履约 | 对应治理权限及事实 | 只解除对应限制，重新组合判断 | 撤下、成交、其他限制不随之清除 |

物品生命周期保持原需求定义；隐藏、账号受限、争议是独立条件。接口不允许任意客户端直接提交目标状态跳转。

## 3 并发和幂等

建议锁序：按账户ID排序→物品→订单→争议/治理对象。普通读仅定位，锁后当前读再判断。相同意图重放先核身份归属再查回执，不重新执行新业务资格条件；异负载拒绝。逻辑唯一与数据库唯一约束同时存在，竞争失败明确返回409，不能笼统用500替代预期业务冲突。

死锁/锁超时可返回可重试冲突，客户端保留原意图；服务端自动重试必须有上限，并重跑完整事务，不能只补写半步。D用MySQL多连接、屏障和前后数据断言检查，测试设施不得变成产品后门。

## 4 历史、隐私和文件

快照自订单成立后只读；举报/处置/补证和关键事实追加留痕。公开列表不返回审核理由或私有治理状态，隐藏对象的收藏只显示不可用占位；本人和必要治理查询完整记录。文本中的联系方式按公开场景过滤，不因公开脱敏改数据库原文或私聊原文。

图片存储路径为环境配置，不存个人电脑绝对路径到业务响应。读取由资源入口做对象授权，认证材料不因为有链接就公开；变更图片保留历史订单所需引用。上传数量/容量和可读格式在接口评审锁定，不在无上限状态准入。

## 5 通知和审计

业务事务把必要审计和Outbox同时持久化；事务提交后独立投递。待发送/失败可按有上限批次和退避重试，事件唯一键阻止重复最终通知。Outbox写失败属于业务未提交；提交后最终通知投递失败不撤销交易，两种故障分别验证。

审计包含操作者、对象、动作、版本、前后态、理由、时间和结果，公开页面不返回。失败审计在业务事务退出后按需要独立追加，不用另一个连接等待自己尚未释放的写锁。
