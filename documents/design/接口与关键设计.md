# 接口与关键设计

版本3.0，2026-11-12。本文件规定校园二手交易与物品流转平台的会话、标识、业务接口、状态码和关键协作规则。完整路径、请求字段和响应模型见[OpenAPI](openapi.yaml)。

## 1 会话、标识与错误

所有业务接口以`/api`开头。客户端首先调用`GET /api/me`取得`{user,csrf}`；匿名访问时`user=null`。注册和登录成功后更新Session标识及CSRF令牌，退出登录后原会话失效。POST、PUT和DELETE等写请求携带`X-CSRF-Token`，用户身份由服务端Session确定。

`/me.user.id`、物品`seller_id`、订单`buyer_id/seller_id`和聊天账号编号使用统一的账号业务标识。编号用于关联对象，后端仍根据角色、对象归属和业务状态执行授权。

正常响应使用JSON，错误响应使用`{message}`。主要状态码如下：

| 状态码 | 含义 |
|---|---|
| 400 | 参数格式或业务条件不符合要求 |
| 401 | 会话中没有有效登录身份 |
| 403 | CSRF校验、角色权限或对象权限不符合要求 |
| 404 | 请求的业务资源不存在 |
| 409 | 唯一约束、状态竞争或重复操作冲突 |
| 500 | 服务执行过程中出现未预期异常 |
| 503 | 数据库或依赖服务暂时不可用 |

## 2 物品接口

`POST /items`用于发布物品，`PUT /items/{id}`用于修改物品。主要字段包括`title/category/description/price/image_id`。物品关键内容修改后形成新版本并进入审核流程；审核操作携带当前`version`，保证审核对象与展示版本一致。

发布及编辑请求可以携带`Idempotency-Key`。同一操作者使用相同意图键和相同内容重试时返回原结果；相同意图键对应不同内容时返回业务冲突。前端在一次提交及其网络重试中沿用同一意图键。

公开物品列表只返回允许公开展示的字段和状态。卖方本人及管理员通过受保护接口访问编辑、审核和治理所需信息。

`GET /items/mine`按页返回本人发布的全部状态物品，响应包含`items/page/size/total/totalPages`。页码从1开始，每页默认20条、最多50条；请求页码超过末页时返回最后一页。

## 3 订单与交付接口

下单请求携带`item_id`、`version`和必填的`Idempotency-Key`。意图键格式为`[A-Za-z0-9_-]{8,100}`。订单动作包括接受、拒绝、交付登记、买方确认、取消和提醒。

订单动作遵循角色和阶段约束：

| 动作 | 执行角色 | 主要条件与结果 |
|---|---|---|
| 下单 | 买方 | 物品版本可交易，创建订单快照并建立有效占用 |
| 接受/拒绝 | 卖方 | 待卖方确认阶段；接受后进入待交付，拒绝后释放占用 |
| 交付登记 | 卖方 | 待交付阶段，登记交付事实并进入待买方确认 |
| 买方确认 | 买方 | 已有交付登记，确认后订单完成、物品成交 |
| 普通取消 | 交易当事人 | 满足取消边界，终止订单并重新计算物品状态 |
| 提醒 | 交易当事人 | 在允许的阶段登记提醒事件并生成通知 |

交付、确认和取消按动作要求提供`declared=true`；拒单、交付和取消填写相应说明。订单详情返回`{order,delivery,reviews}`，由交易当事人或具有治理权限的管理员访问。

## 4 收藏与评价

收藏接口支持三种操作：

- POST加入收藏；
- DELETE取消收藏；
- PUT通过`{favorite:true|false}`设置明确目标状态。

重复设置相同目标保持原结果，响应包含`ok/favorite/item_id`。收藏列表中的非公开物品使用`{id,unavailable:true}`占位，保留用户收藏关系。

交易完成后，买卖双方可各提交一次评价。公开卖方评价接口返回评价数组，公开字段包括`id/score/content/created_at/nickname`。评价与订单的完整关联信息仅通过本人订单详情或治理接口访问。

## 5 聊天与只读状态

- `GET /messages`返回消息数组；
- `GET /messages/context`返回`{messages,readOnly,context_type,context_id}`；
- `POST /messages`发送消息，输入为`{content}`；
- `GET /inbox`返回当前用户的会话摘要。

ITEM场景中，咨询者由当前会话确定，卖方回复时指定咨询人的账号标识。ORDER场景根据订单确定交易双方。订单进入终态后聊天上下文为只读，前端依据`readOnly`隐藏发送入口，服务端同时校验发送条件。

## 6 治理接口

`POST /admin/{kind}/{id}`用于执行管理操作，统一填写`reason`。各类操作字段如下：

| kind | 业务字段与用途 |
|---|---|
| verification | `pass`，审核校园身份申请 |
| item | `pass`和当前`version`，审核物品版本 |
| hide | `hidden`，设置物品展示状态 |
| review | `hidden`，设置评价展示状态 |
| restrict | `restricted`，设置账号交易限制 |
| relist | 核实归属后允许物主重新提交物品 |
| dispute | `outcome=continue/terminate`，终止时提供`evidence_confirmed=true` |
| report | 可携带`event_ref`，保存独立举报处理记录 |

普通文本先去除首尾空白，再按照Java UTF-16代码单元执行长度限制。治理原因上限为1500，订单说明等字段上限为1000。OpenAPI通过`x-max-utf16-code-units`标明相同约束。

## 7 统计与通知

`GET /admin/stats`接受可省略的`from/to`，时间使用带时区的ISO-8601格式。成交统计按照完成时间的左闭右开区间`[from,to)`计算，金额使用完成订单快照；双侧区间满足`from<to`。

业务事务在Outbox中登记通知事件，事务提交后由通知服务独立投递。事件记录保存状态和尝试次数，支持批量补投。`GET /notifications`先处理可投递事件，再返回当前用户最近100条通知。

## 8 接口与架构决策对应关系

| 接口设计 | 关联决策 |
|---|---|
| Session、CSRF和统一错误响应 | Q-RB-02、ADR-RB-05 |
| 物品版本及订单状态转换 | ADR-RB-02 |
| 意图键和稳定回执 | ADR-RB-03 |
| Outbox和通知补投 | ADR-RB-04 |
| 公开字段与受保护详情 | ADR-RB-05 |
| 管理统计与治理入口 | Q-RB-05 |
