# 接口与关键设计

V2，2026-11-26。依据当前代码基线 `f64115dc950cc29238073195e3a51a5767686803` 整理。按用户本次决定，接口形态采用该版本，替代此前候选接口中不同的包装、标识及参数约定。[OpenAPI](openapi.yaml)供调用方使用，[问题记录](../../reports/V3问题清单.md)跟踪实现缺陷。

本次只调整接口文档，不改需求说明书、代码、数据库或历史测试原件；技术接口对齐不等于删除业务要求，也不等于全员阶段验收。

## 1. 会话、标识与错误

所有接口以`/api`开头。先调用`GET /api/me`取得`{user,csrf}`；匿名时`user=null`。注册、登录成功更换Session标识和CSRF，退出使会话失效。POST/PUT/DELETE等写请求带`X-CSRF-Token`，身份从服务端Session读取。

`/me.user.id`、物品`seller_id`、订单`buyer_id/seller_id`及聊天相关账号编号统一使用`accounts.id`。当前不引入独立`public_ref`，不要求前端转换编号。编号用于关联对象，后端继续检查本人、交易当事人或必要治理范围；知道编号不代表有读取权限。

正常响应为JSON，错误为`{message}`。常见状态为400参数或业务条件不符、401未登录、403越权或CSRF失败、404资源不存在、409记录或锁冲突、500未预期异常；健康检查数据库不可用返回503。个别业务通过通用条件校验返回400，不能把所有权限类业务失败强写成403。

## 2. 物品和订单

`POST /items`、`PUT /items/{id}`接收`title/category/description/price/image_id`，编辑不要求请求体提供`version`。创建新版本后待审；审核物品时必须提交当前`version`。有有效占用时禁止修改。

发布/编辑的`Idempotency-Key`在服务端为可选：带键时，同一操作者、同键同内容返回原物品/版本，同键异内容400；不带键按新请求处理。前端正常提交仍携带键，重试沿用同一意图键。

下单及订单动作的`Idempotency-Key`必填，格式`[A-Za-z0-9_-]{8,100}`。下单输入`item_id/version`；动作包含accept、reject、deliver、confirm、cancel、remind。交付/确认/取消按动作要求提供`declared=true`；拒单、交付、取消需要相应说明。订单详情返回`{order,delivery,reviews}`，访问仅限当事人或专门治理入口授权的管理员。

## 3. 收藏与评价

收藏用POST加入、DELETE取消或PUT明确设置`{favorite:true|false}`。重复同目标不反转，响应含`ok/favorite/item_id`。GET收藏列表中不可见条目只返回`{id,unavailable:true}`。

`GET /sellers/{id}/reviews`当前返回评价数组，无评价为`[]`；不使用`PublicSeller`包装，不返回`reputation`汇总对象。当前字段为`id/score/content/created_at/nickname`，不返回order_id、author_id和target_id。双方评价通过本人订单评价接口各提交一次，公开卖方列表只取未隐藏的买方评价。

信誉汇总不是当前接口承诺的字段。后续如仍要增加，单列功能任务，先确定计算口径再扩接口，不能要求A按不存在的对象解析当前数组。

## 4. 聊天与只读状态

- `GET /messages`返回消息数组。
- `GET /messages/context`返回`{messages,readOnly,context_type,context_id}`，前端据此显示发送框或只读提示。
- `POST /messages`发送内容，输入`{content}`；三者的查询参数均为`type/object/peer`。

ITEM场景中，非卖方可留空peer，由本人会话确定咨询人；卖方回复须指定真实咨询人账号id，不能进入不存在的线程。ORDER场景忽略peer，从订单确定双方。终态订单只读，服务端发送检查独立执行。`GET /inbox`的`peer_id`也使用当前账号id，不使用公开引用转换。

## 5. 治理、统计与通知

`POST /admin/{kind}/{id}`统一需要reason；以下字段按动作使用。

| kind | 业务字段 |
|---|---|
| verification | pass；按申请id定位，不要求version |
| item | pass、当前version |
| hide、review | hidden目标布尔值 |
| restrict | restricted目标布尔值 |
| relist | 核实归属后授予重新提交许可，物主修改后仍须审核 |
| dispute | outcome=continue/terminate；terminate还需evidence_confirmed=true |
| report | 可选event_ref；各举报保留独立回执 |

普通文本按Java的UTF-16代码单元计数，先trim，再执行长度限制。reason输入上限1500；订单说明等按对应字段1000。补充平面字符如`😀`占两个代码单元，不再将该计数约定单独列为缺陷。OpenAPI用`x-max-utf16-code-units`明确实际约束。V6迁移已扩容认证和物品审核原因列，合法输入完整保存，通知另按上限截取摘要。

`GET /admin/stats`接受可省略的from/to，解析带时区的ISO-8601时刻。成交按完成时间`[from,to)`，金额按完成订单快照；发布和举报数为累计值。金额为JSON数字，零成交金额可为0。有效双侧区间应满足from<to，反向及相等区间均返回400，不作为正常的零成交结果。

通知通过事务内Outbox登记、提交后独立事务投递；失败保留重试，不能撤销已提交业务。`GET /notifications`先补投，再返回本人最近100条。业务SQL失败则整体回滚。
