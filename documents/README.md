# 工程文档入口

修订日期：2026-11-12。本目录集中保存校园二手交易与物品流转平台的需求、设计、阶段实施、测试与证据材料。需求规格说明书作为业务基线，设计和阶段文档由全组共同维护，A、B、C负责对应实现与自测，D负责独立验证和验收材料。

## 1 阅读顺序

1. [组织架构](组织架构.md)与[协作流程](协作流程.md)：了解成员职责、目录和版本协作方式。
2. [需求规格说明书](requirements/需求规格说明书.md)：明确业务范围、用例、规则和质量要求。
3. [架构讨论稿](design/架构设计_讨论稿.md)、[架构决策](design/架构确认与决策记录.md)与[架构基线](design/架构设计_基线版.md)：了解总体技术方案及取舍。
4. [数据与状态](design/数据与状态设计.md)、[接口与关键设计](design/接口与关键设计.md)、[OpenAPI](design/openapi.yaml)及[运行配置](design/运行与配置说明.md)：了解实现契约。
5. [阶段计划](stages/阶段计划.md)、[任务索引](stages/任务索引.md)、[阶段准入](stages/阶段准入记录.md)与[阶段验收](stages/阶段验收记录.md)：了解V1—V3实施过程。
6. [测试用例](testing/测试用例.md)、[系统测试记录](testing/系统测试记录.md)、[系统测试报告](testing/校园二手交易与物品流转平台系统测试报告.docx)、[质量处理记录](testing/质量处理记录.md)与[V3问题修复及复验记录](testing/V3问题修复与复验记录.md)：了解验证范围和结果。
7. [证据索引](evidence/证据索引.md)：核对接口、数据库、浏览器、启动及升级的原始结果。

## 2 目录职责

| 目录 | 内容 | 维护方式 |
|---|---|---|
| requirements/ | 需求规格说明书、业务规则、模型和验收标准 | 全组作为业务基线共同使用 |
| design/ | 架构、ADR、数据状态、接口、OpenAPI及运行配置 | 全组共同维护 |
| stages/ | 版本计划、任务安排、准入与验收 | 全组维护，D整理验收材料 |
| testing/ | 测试用例、阶段验证、系统测试和质量处理 | D主责，A/B/C提供自测及复核 |
| evidence/ | 各阶段原始测试、截图、日志和数据结果 | 各成员提供，D统一索引 |

## 3 文档同步原则

- 需求变化同步需求条目、业务规则、设计、接口及验收标准。
- 接口变化同步OpenAPI、调用方、测试用例和运行说明。
- 数据变化同步升级脚本、状态设计和数据库验证。
- 每个版本使用同一份代码与文档基线开展测试和验收。
- 正文概括结论，原始结果统一放入证据目录并通过编号引用。
- GitHub读取、提交、推送、PR及Issue操作按照项目约定逐批确认。

## 4 当前文档成果

设计目录已经形成统一架构基线；阶段目录记录V1核心闭环、V2功能集成和V3系统测试安排；测试目录覆盖功能、权限、事务、可靠性、数据升级和浏览器交互，并保存V3问题修复及复验结果；证据目录保存V1、V2阶段的原始验证结果。
