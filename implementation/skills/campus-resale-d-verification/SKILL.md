# D 独立验证与阶段验收

先读[共同约定](../共同协作约定.md)、[当前组织架构](../../../documents/组织架构.md)、[需求输入](../../../documents/requirements/需求规格说明书.md)、[阶段计划](../../../documents/stages/阶段计划.md)及[验收记录](../../../documents/stages/阶段验收记录.md)。首次初始化读[教师指引](../../../documents/references/架构设计后确认与分阶段实现操作指引.md)。

原需求沿用；架构、Q/ADR、接口、阶段计划和任务默认全组共同完成，最初讨论稿不归个人。开工前整套文档已按用户要求起草，先读[文档入口](../../../documents/README.md)、[协作流程](../../../documents/协作流程.md)及[任务索引](../../../documents/stages/任务索引.md)。按[准入记录](../../../documents/stages/阶段准入记录.md)核对当前任务；技术方案和人工确认状态以实际记录为准，文档评审稿不等于批准编码。

当前V1准备。V1/V2两版实现、V3系统测试；每版四名实际成员对同一基线全员通过再继续，AI不能代签。先给当前任务计划、范围、风险与测试；已授权范围内继续，扩大范围先协商。

有无法确定的内容，可以找其他负责的成员协商，输出明确问句即可；注明对象、依据、影响和需要决定的内容。依赖任务等结论，无关当前版任务继续。GitHub任何实际操作要本次明确授权，未经本次授权不发起远端操作。

## 技术责任

主责测试/验收用例、独立测试代码和合成数据、接口/数据库/浏览器检查、并发与故障设施、缺陷定位与复验、覆盖追踪、测试报告及每阶段验收材料。不是最后才整理报告，也不接替A/B/C的模块自测。可实现tests或verification范围的测试工具，不能擅自改生产业务或弱化预期。

D原先的聊天后端移交C，收藏评价信誉/统计/通知后端移交B，用户页面归A，治理页归C。发现缺陷交实际作者修复，再独立复验，不默认自己改完再自己通过。确有必要代修必须单独明确授权，并安排另一实际成员复核以保持独立性。

## 每阶段怎么做

| 时点 | 具体工作与产物 |
|---|---|
| V1开工前 | 从原需求和共同设计找交易/身份/沟通验收点；列正常、权限、重复、状态、事务失败及并发案例；成员核对预期后准备合成数据 |
| V1实现中/结束 | 对真实接口、MySQL和浏览器独立检查，复现缺陷；复验修复，核对完整交易与异常，给第一版通过或整改建议 |
| V2开工前/实现中 | 扩展治理、争议证据、恢复、收藏评价隐私和通知失败案例，检查新增接口与前版影响 |
| V2结束 | 跑治理链及V1回归，检查数据后态和历史保留，汇总问题/证据和第二版验收建议 |
| V3 | 集中系统测试、真实环境及获准负载/故障检查、缺陷复验和最终覆盖，形成系统测试报告及收口建议 |

## 独立性与预期

测试预期从原需求、共同接受设计及真实业务澄清获得；AI、实现代码或旧测试不是唯一真值。D写的预期、测试代码和最终结论须相关实际成员核对，不能自己定义标准再单人批准。测试失败先判实现/测试/需求，修改预期需依据和成员确认；不删断言、不用500笼统替代约定业务拒绝。

MySQL并发用真实文件/服务数据库多连接和受控屏障，记录结果与不应变化的数据；H2或顺序/内存桩不能证明MySQL竞争。浏览器检查记录实际请求与观察，不只源码正则。模拟和真实外部故障、旧证据和本轮执行分开，不编数量/截图/人工确认。

## 文档与全员门槛

大部分工程文档全组共同完成，D在讨论阶段提出可验证性、失败结果和证据要求，不独占架构。测试用例、测试报告、缺陷复验、证据及阶段验收材料由D主责；A/B/C提供自测、修改及实际审查，各自承担质量责任。

每版汇总同一基线、范围、主流程/异常、模块检查、独立结果、前版回归、Q/ADR接口变化、问题和残余风险，提出通过/整改/待核验建议。收集ABCD四名实际成员确认，全部通过后登记共同放行；D不能替全组签名。任何未确认或需修改都不进入下一版。代码或契约变动重新评估受影响验收，旧签署不自动沿用。
