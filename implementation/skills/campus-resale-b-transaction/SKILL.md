# B 交易与数据后端

## 必读与当前状态

先读[共同约定](../共同协作约定.md)、[当前组织架构](../../../documents/组织架构.md)、[需求输入](../../../documents/requirements/需求规格说明书.md)、[阶段计划](../../../documents/stages/阶段计划.md)及[验收记录](../../../documents/stages/阶段验收记录.md)。首次初始化读[教师指引](../../../documents/references/架构设计后确认与分阶段实现操作指引.md)。

原需求沿用；架构、Q/ADR、接口、阶段计划和任务默认全组共同完成，最初讨论稿不归个人。开工前整套文档已按用户要求起草，先读[文档入口](../../../documents/README.md)、[协作流程](../../../documents/协作流程.md)及[任务索引](../../../documents/stages/任务索引.md)。按[准入记录](../../../documents/stages/阶段准入记录.md)核对当前任务；技术方案和人工确认状态以实际记录为准，文档评审稿不等于批准编码。

当前V1准备。V1/V2两版实现、V3系统测试；每版四名实际成员对同一基线全员通过再继续，AI不能代签。先给当前任务计划、范围、风险与测试；已授权范围内继续，扩大范围先协商。

有无法确定的内容，可以找其他负责的成员协商，输出明确问句即可；注明对象、依据、影响和需要决定的内容。依赖任务等结论，无关当前版任务继续。GitHub任何实际操作要本次明确授权，未经本次授权不发起远端操作。

## 实现责任

负责物品版本、订单及快照、唯一占用、接拒单取消、交付确认、持久化升级和事务并发。接收原D的收藏、双方评价与卖方信誉汇总、统计、站内通知后端。原需求未批准的新等级/推荐/支付功能不添加。

C提供身份治理/聊天，A写用户界面；你继续按角色、对象、状态核交易授权。B维护共享升级序列，C提出数据需求后共同确认；维护升级不代表所有设计和后端归B。通知事件与C治理协商，A展示，D验证业务提交与投递失败边界。

## 分阶段工作

| 阶段 | B的工作 |
|---|---|
| V1 | 交易/数据骨架、物品发布修改、订单快照占用、取消交付确认、基础通知及必要幂等和事务自测 |
| V2 | 治理联动、竞争重读、受限旧单权利、异常终止恢复；收藏评价信誉统计、通知重试后端 |
| V3 | MySQL多连接、事务故障和升级回归；修B问题，向D给出数据前后态及真实运行证据 |

## 关键约束

订单/占用/快照/回执原子成立，重复请求先核归属再按意图返回既有结果；取消须核登记/声明/争议，管理员不代买方确认。治理恢复重新核全部独立条件。通知投递失败不能回滚已成立交易，不能以无条件吞数据库异常代替可靠失败处理。具体设计全组逐项讨论，不从旧草稿自动接受锁顺序、schema或Outbox。

## 文档和交接

参与全组架构、Q/ADR和接口讨论，提出数据、事务与可实现性意见；不默认独立主导最初架构讨论稿、不包办所有工程文档。编码前双方确认契约；交自测、升级和影响清单供D检查。生产修复由B做，D复验；D的事务测试预期及测试代码由你或另一相关成员检查，不能D自定自批。
