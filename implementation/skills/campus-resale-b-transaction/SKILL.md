# B 交易后端与架构设计

## 开始时读取

先读[共同协作约定](../共同协作约定.md)、[工程文档基线](../../../documents/README.md)、[阶段计划](../../../documents/stages/阶段计划.md)和[阶段验收记录](../../../documents/stages/阶段验收记录.md)。[原需求规格说明书](../../../documents/requirements/需求规格说明书.md)是已有输入：首次认识范围，做任务时按FR/UC/BR/ST定位原文，不重写需求、不凭代码反推规则。

首次初始化读[教师操作指引](../../../documents/references/架构设计后确认与分阶段实现操作指引.md)，按其中Q、ADR、接口、测试、任务、人工复核和验收要求执行。[记录模板](../../../documents/记录模板.md)提供字段；当前尚未形成的设计或任务先列缺项，不能当已确认。

当前V1准备，两版实现V1/V2，一版系统测试V3，没有另设V0。先输出本版范围、已有依据、计划/文件范围、依赖及测试，等实际同学批准对应任务；已授权任务在范围内继续，不反复确认。每版四位实际成员对同一基线全部通过才进下一版。AI只能建议，不能代签。

有无法确定的内容，可以找其他负责的成员协商，输出问句就行。说明接收人、需求/接口、冲突和选项、阻塞范围。受影响任务等结论，本版无关任务继续；不自动对外发消息或擅改共享协议。GitHub任何读写操作需本次用户明确确认，当前无远端授权。

## 每批交付

实现与文档同步，引用同一需求和快照；提供变更、契约影响、真实测试与回归、另一成员审查及后续问句。自己的测试自己准备和执行，AI可代跑但不能代替实际成员核对与验收。遇到失败先判实现/测试/需求，不删断言追全绿。旧代码复用注明来源，旧测试不算新轮结果；不自动启动服务器或云资源。

## 实现责任

负责物品版本与历史、订单及成立快照、唯一有效占用、接拒单、取消、交付登记和买方确认，以及共享数据库迁移。技术参考Java17/Spring Boot/MyBatis/MySQL，不直接复刻旧千行Service作为模块划分。C写认证治理，D写沟通通知评价，各人负责自己接口，B统合数据/契约与后端依赖。

C提供会话/鉴权能力，交易服务仍核参与者、对象与状态。C/D提出表结构和约束，你组织同一迁移序列，避免私建多套模型；迁移与数据升级需按任务评审，不自动清库重建。

## 分阶段交付

| 版本 | 具体交付 | 关键检查 |
|---|---|---|
| V1 | 模型迁移、发布修改版本、订单快照/占用、接拒单取消、交付确认、交易接口 | 一物一有效占用；同意图重试一次效果；下单版本匹配；买方本人确认；失败不留孤单或占用 |
| V2 | 治理与占用联动、限制账号旧单权利、争议期间动作、异常终止与恢复、竞争重查 | 解封/取消不绕过其他冻结条件；锁后用最新状态；旧快照不改写；与C治理、D通知衔接 |
| V3 | 真实MySQL多连接竞争、事务故障、幂等、约束与迁移检查 | 运行本轮目标环境测试、记录数据前后态；H2结果不算MySQL并发；修B缺陷并回归 |

## 兼任架构与ADR统合

组织documents/design内架构讨论稿，说明技术结构、模块边界、数据流和运行拓扑；各人供自己的设计，不包办所有文稿。C先澄清真实业务歧义，再评审相关ADR；已有原需求明确的规则直接引用。ADR记录备选、理由代价、验证、实际接受/拒绝/暂缓及重评条件，不能把AI推荐当决定。

确认后的范围单独整理架构基线，保留讨论稿和未决项。接口与关键设计按当前版本细化：调用双方确认方法、schema、错误及数据变化、状态权限、幂等并发、事务与TC。查询说明范围分页，写操作给正常/业务失败/重复示例。协议由提供方编写，B统合不等于单方面改C/D接口。

重要设计包括订单/占用/回执同事务，账户及交易锁顺序、旧快照保留，通知投递与业务提交边界。与D先保证V1通知故障行为符合原需求，不能声称V2之前允许丢事务；是否Outbox等技术手段由ADR比较确认。
