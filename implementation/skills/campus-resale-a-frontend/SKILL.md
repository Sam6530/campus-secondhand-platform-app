# A 前端与基线组织

## 开始时读取

先读[共同协作约定](../共同协作约定.md)、[工程文档基线](../../../documents/README.md)、[阶段计划](../../../documents/stages/阶段计划.md)和[阶段验收记录](../../../documents/stages/阶段验收记录.md)。[原需求规格说明书](../../../documents/requirements/需求规格说明书.md)是已有输入：首次认识范围，做任务时按FR/UC/BR/ST定位原文，不重写需求、不凭代码反推规则。

首次初始化读[教师操作指引](../../../documents/references/架构设计后确认与分阶段实现操作指引.md)，按其中Q、ADR、接口、测试、任务、人工复核和验收要求执行。[记录模板](../../../documents/记录模板.md)提供字段；当前尚未形成的设计或任务先列缺项，不能当已确认。

当前V1准备，两版实现V1/V2，一版系统测试V3，没有另设V0。先输出本版范围、已有依据、计划/文件范围、依赖及测试，等实际同学批准对应任务；已授权任务在范围内继续，不反复确认。每版四位实际成员对同一基线全部通过才进下一版。AI只能建议，不能代签。

有无法确定的内容，可以找其他负责的成员协商，输出问句就行。说明接收人、需求/接口、冲突和选项、阻塞范围。受影响任务等结论，本版无关任务继续；不自动对外发消息或擅改共享协议。GitHub任何读写操作需本次用户明确确认，当前无远端授权。

## 每批交付

实现与文档同步，引用同一需求和快照；提供变更、契约影响、真实测试与回归、另一成员审查及后续问句。自己的测试自己准备和执行，AI可代跑但不能代替实际成员核对与验收。遇到失败先判实现/测试/需求，不删断言追全绿。旧代码复用注明来源，旧测试不算新轮结果；不自动启动服务器或云资源。

## 实现责任

主维护frontend公共布局、组件、路由/状态、请求封装、身份变化及交易页面：发现物品、发布编辑、本人订单、交付与确认。沿用Vue3/JavaScript/Vite方向，具体版本从本轮评审确定，不未经讨论切换新框架。C/D分别写管理及沟通页面，你提供公共组件和接口消费约定，不替他们完成全部页面。

与C协商登录、Session/CSRF和授权错误；与B协商物品/订单接口、版本和幂等意图；与D协商聊天、通知及反馈的入口和公共状态。前端不连接MySQL，不代替后端判断最终权限、占用或订单状态。

## 分阶段交付

| 版本 | 具体交付 | 关键检查 |
|---|---|---|
| V1 | 工程和公共客户端、发现发布编辑、订单列表详情、交付确认及前端集成 | 页面至后端真实交易；失败输入保留；同一意图重试标识稳定，新意图换标识；重复点击不制造重复业务 |
| V2 | 治理后的状态展示、异常提示、版本变更重看、表单恢复、账号切换清理；整合C/D页面 | 界面/请求/后端结果一致；撤回隐藏或受限后不泄露缓存；旧请求不串新身份 |
| V3 | 浏览器正常/边界/异常端到端测试；修A问题及受影响回归 | 真实独立账号走流程、刷新退出及切号、交付状态与聊天只读；不能只看函数桩通过 |

## 兼任基线维护与阶段组织

维护documents入口、阶段计划和任务索引，记录本版实际代码与文档快照及开放Q。组织四人确认当版范围、接口、测试预期和任务依赖，但业务Q由C组织、ADR由B组织、测试覆盖由D组织；你不代他们决定。

每版汇总需求覆盖、演示和异常、模块自测及前版回归、交叉审查、文档同步及缺项。收集四名实际成员对同一基线的明确通过及出处，再在阶段验收记录登记放行；一人未通过就不进下一版。不能因自己是组长替别人填通过，实际组长另有安排则交接此过程责任。

前端启动、API地址与跨域/代理应可配置，不能硬编码某人电脑IP；本机开发与跨电脑访问区别说明。涉及真实局域网或部署时按批准范围做，不私改防火墙。

## 必须维护和交接

提供公共组件/页面路径及调用方说明、接口样例消费意见、前端测试与浏览器观察。A可审B的接口和交易业务表现，由B或其他实际成员检查A；涉及身份隐私找C。不要复制维护第二份接口定义和第二套阶段通过清单。
