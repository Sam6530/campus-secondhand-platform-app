原需求沿用；架构、Q/ADR、接口、阶段计划和任务默认全组共同完成，最初讨论稿不归个人。开工前整套文档已按用户要求起草，先读[文档入口](../../../documents/README.md)、[协作流程](../../../documents/协作流程.md)及[任务索引](../../../documents/stages/任务索引.md)。按[准入记录](../../../documents/stages/阶段准入记录.md)核对当前任务；技术方案和人工确认状态以实际记录为准，文档评审稿不等于批准编码。

当前V1准备。V1/V2两版实现、V3系统测试；每版四名实际成员对同一基线全员通过再继续，AI不能代签。先给当前任务计划、范围、风险与测试；已授权范围内继续，扩大范围先协商。

有无法确定的内容，可以找其他负责的成员协商，输出明确问句即可；注明对象、依据、影响和需要决定的内容。依赖任务等结论，无关当前版任务继续。GitHub任何实际操作要本次明确授权，未经本次授权不发起远端操作。

## 实现责任

负责注册登录、会话CSRF、认证、审核、举报争议补证处置、隐藏限制恢复及对应管理页面；接收原D的聊天后端和对象访问控制，统一物品咨询/订单会话参与人及终态只读规则。A写用户聊天页面，B提供订单状态和通知服务。C不能只交鉴权工具而忽略自身业务接口。

向B提供通用身份能力，业务模块继续核具体对象和状态。治理不得私改订单半个状态，与B协商原子治理接口；管理页用A公共组件。共享模型和迁移向B提出需求后共同确认，不建第二套账户或订单表。

## 分阶段工作

| 阶段 | C的工作 |
|---|---|
| V1 | 身份会话认证、商品审核及管理页，基础聊天和隐私/只读、对象授权自测 |
| V2 | 举报争议补证结案、隐藏限制恢复和治理留痕、聊天受限旧单权利及治理联动，补统计管理页 |
| V3 | 认证权限、治理状态证据、恢复和聊天访问回归；修C缺陷，供D独立验证 |

## 文档和交接

原需求只读引用，不重写、不擅自变更。架构、Q/ADR、接口和计划由全组共同完成，不默认由C独占业务Q或代学校确认。发现歧义向相关人提出具体问句，实际确认人负责决定；记录人可轮值。按原规则核对预期，不能仅以当前代码行为判断正确。

给A交管理/聊天接口与界面需求，给B交授权和治理事件，给D交自测及合成场景。缺陷由C修，D复验；D编写的治理/聊天验收标准和测试代码由C及另一相关实际成员复核。
