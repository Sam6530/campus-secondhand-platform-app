# C 身份治理与业务澄清

## 开始时读取

先读[共同协作约定](../共同协作约定.md)、[工程文档基线](../../../documents/README.md)、[阶段计划](../../../documents/stages/阶段计划.md)和[阶段验收记录](../../../documents/stages/阶段验收记录.md)。[原需求规格说明书](../../../documents/requirements/需求规格说明书.md)是已有输入：首次认识范围，做任务时按FR/UC/BR/ST定位原文，不重写需求、不凭代码反推规则。

首次初始化读[教师操作指引](../../../documents/references/架构设计后确认与分阶段实现操作指引.md)，按其中Q、ADR、接口、测试、任务、人工复核和验收要求执行。[记录模板](../../../documents/记录模板.md)提供字段；当前尚未形成的设计或任务先列缺项，不能当已确认。

当前V1准备，两版实现V1/V2，一版系统测试V3，没有另设V0。先输出本版范围、已有依据、计划/文件范围、依赖及测试，等实际同学批准对应任务；已授权任务在范围内继续，不反复确认。每版四位实际成员对同一基线全部通过才进下一版。AI只能建议，不能代签。

有无法确定的内容，可以找其他负责的成员协商，输出问句就行。说明接收人、需求/接口、冲突和选项、阻塞范围。受影响任务等结论，本版无关任务继续；不自动对外发消息或擅改共享协议。GitHub任何读写操作需本次用户明确确认，当前无远端授权。

## 每批交付

实现与文档同步，引用同一需求和快照；提供变更、契约影响、真实测试与回归、另一成员审查及后续问句。自己的测试自己准备和执行，AI可代跑但不能代替实际成员核对与验收。遇到失败先判实现/测试/需求，不删断言追全绿。旧代码复用注明来源，旧测试不算新轮结果；不自动启动服务器或云资源。

## 实现责任

主责注册登录、Session/CSRF、身份与角色基础、校园认证、物品审核、隐藏/账户限制、争议举报补证及处置审计，并完成对应管理页面。使用A的布局/客户端，与B共享模型迁移，不能独立创建另一套账户或订单状态。

向B/D提供统一鉴权能力和授权约定，业务负责人仍落实具体对象检查。校园认证按原需求人工审核，不能假接入学校SSO或把AI模拟当业务方批准。管理员权限不自动等于可替买方确认交付。

## 分阶段交付

| 版本 | 具体交付 | 关键检查 |
|---|---|---|
| V1 | 登录会话、CSRF、授权、校园认证/审核、物品版本审核及管理页 | 未认证新业务拒绝；当事人/管理员对象权限；只审当前版本；密码语义不被静默改写 |
| V2 | 隐藏限制、举报独立回执、争议申请补证处置、恢复与审计、对应界面 | 补证不丢失且结案后不暗改依据；治理理由/事实留存；恢复仍检查B占用及其他条件 |
| V3 | 认证角色越权、治理与争议状态、证据访问、隐私和恢复回归 | 原需求驱动预期、真实接口/数据库及页面证据；修C缺陷、另一成员复核 |

## 兼任业务Q组织，绝不重写需求

原需求说明书已经存在，读并按FR/UC/BR/ST引用，不安排重新编写、换编号或压缩。需求已明确则直接核对，不另造待决问题阻塞工作。歧义、文档冲突或新要求记录Q，列原文、选项及代价、影响任务和可检验决定，找相关实际成员确认。

C组织澄清不等于C独自代表学校或老师。教学设定写清身份，涉及真实业务或课程范围争议按教师指引升级。问题回答后同步设计、接口、状态及测试，另一成员复核后才能关闭；涉及真正改变原需求时先提出变更申请，未明确批准前不修改原文。

核对测试预期的业务来源：不能只因为实现返回某状态就将它设为正确。D整理测试追踪，你与相关模块负责人确认预期，不能代替他们审实现。ADR由B组织，接口变更由提供/调用方共同确认。

## 必须维护和交接

交付认证治理接口与页面、权限/状态和处置设计、Q同步记录、真实测试证据。与B核对治理和订单占用联动，与D核对私聊/通知/评价访问范围。C也参加每版整条链验收，不能只确认认证页面能打开；交叉审查必须是真实另一成员。
